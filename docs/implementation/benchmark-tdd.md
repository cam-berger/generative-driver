# Benchmark implementation evidence

Approved seam: benchmark run, score and compare. Tests use the public evaluator functions and CLI, independent expected observations, and temporary artifacts. Candidate source equality is never a verdict.

1. Password and pinned ciphertext hash: test failed because the benchmark truth API did not exist. Added authenticated AES-GCM evidence storage with PBKDF2-HMAC-SHA256; the known evidence round-trips, wrong passwords and pins fail.
2. Independent behavior score: test failed because the public score API did not exist. Literal reference temperature/duty/refusal observations pass; deliberately wrong scaling/effect and missing observations fail. Candidate implementation text is not a scoring input.
3. Report comparison: missing comparison API produced the red result. Added case/evaluator/seed/execution compatibility, separately labelled agent/compiler changes and null-preserving cost/time differences. Combined changes are labelled as complete-system comparisons.
4. Setup benchmark: missing run API produced the red result. The implementation calls the actual toolchain validator, recorded probe, emitter and package checker, relocates the package, then runs its public replay command in an isolated Python process. Its literal expected temperature is 21.5, execution is scripted replay, usage is unknown and it never counts as an agent benchmark.
5. Acquisition acceptance: a worker claim without imported bytes failed; a real acquire tool call with the pinned firmware succeeds. Blind preparation then verifies neutral sealed input names and absence of evaluator source/password.
6. Repair preparation: retrying a prepared attempt failed. Separate interpretation attempt, controller revision and firmware revision preserve the initial image during a model repair and seal neutral observed defects into the new kit.
7. Qualification acceptance: a structurally valid model without predicted replies was incorrectly accepted (red). The gate now requires host qualification with every declared operation covered, retaining collection/structural/qualification evidence separately.
8. Saved score: an existing passed label with wrong replay observations is rejected by independent rescoring. Reports cannot substitute a verdict label for recorded observations.
9. Accepted package provenance: the portability review's integration test failed with accepted handoffs but missing mutable source state. Preparation now resolves frozen controller artifact names, emits from accepted model/probe bytes, and rejects a different model or a historical non-current runtime before package execution.
10. Physical prerequisites: the missing physical adapter initially raised unsupported. The profile now requests explicit binding before any agent/device I/O and accepts independent observations only through the controller's operator response channel.

Native reference calibration exercised Renode, shared runtime and relocated package without calling a language model. Reference effect checks passed; fresh package calls initially failed with a real not-armed reply. Diagnosis found the base platform's SysTick clock contradicted the owned firmware reset clock. Correcting the encrypted emulator recipe and explicitly pausing virtual time between package calls restored the intended behavior. The final calibration established temperature/read, requested output and disarm; identity refusal before operation on the updated firmware; revised model qualification, re-probe, emission and fresh reuse; and rejection of a deliberately wrong decoder scale. Selected observations, source/build provenance and limitations are encrypted with the case evidence. This is harness calibration, not a model baseline or physical validation.

11. Stage comparison: a fixture with a changed host environment and failed-to-passed interpretation initially produced no dimension or stage changes (red). Added explicit per-stage worker/elapsed/tool/attempt/token deltas and workflow/evaluator status changes, keeping missing counters unknown.

Evaluator rebuild verification found a missing `libgcc` link flag; the helper now links the compiler arithmetic helpers. Running the public rebuild path with the recorded compiler reproduces both published firmware SHA-256 values. No model execution is involved.

12. Changed physical reference: a public stimulus score test started red without the scorer. A fresh matching value now passes; a constant value after changed reference and an unchanged reference both fail. BME280 case/evaluator version 2 carries this criterion in its encrypted evidence.
13. Retry evidence: reuse initially accepted a successful observation from a previous attempt (red). Every package preparation now creates a unique attempt identifier, recorded by package execution and required by current reuse/maintenance checks in both profiles.
14. Fault ownership: a granted set-output transport failure must remain a host fault even when the intentional no-grant check also reports refusal. Evaluator calls now record grants; the public fault classifier excludes only the intentional operator refusal and preserves granted host/operator failures.
15. Intervention reporting: a public summary fixture failed because original/effective budgets were missing (red). The report now extracts permitted control-event fields, keeps the existing operator-response count, and separately records budget, authorization, cancellation and resume events. Private operator message/observation content is excluded from this timeline. The test preserves stopped wall time and unknown active time, and identifies source hashes as exporter provenance. All six reporting tests pass.
