# Open notes from the untangle Run

Status: needs-triage

Findings noticed during the untangle Run and left unfixed. Each was checked against the tree on 2026-11-19. The Run's records are in Git history at commit `7b53448`, under `docs/features/untangle/`.

- `docs/client-interface.md:5`: the document gives `call(method, params, home)` and names neither the options `autostart` and `read_timeout` of `call` (`src/generative_driver/client.py:336`) nor the variable `GENERATIVE_DRIVER_HOME` that `default_home()` reads (`client.py:204`). The client that left this repository used all three, so the document does not cover what a client needs.
- `docs/client-interface.md:160`: the document says the rows of `handoffs` are read in `rowid` order. The service reads them `ORDER BY created` (`src/generative_driver/configurator.py:1275` and `:2409`), and the two orders differ if the clock steps back between two handoffs.
- `docs/client-interface.md:166`: "saved candidates" for the replay executor are named here, and line 189 says how a `start` names one. The document never says what a saved candidate is, though `AGENTS.md` asks for terms to be defined on first use.
- `docs/extending-drivers-and-mcp.md:113`: the list of evidence kinds to label still holds "native reference calibration". The tool has no calibration; the term belonged to the benchmark that left this repository.
- `src/generative_driver/_toolchain/interface.py:24`: `RUNTIME` here is the folder of `interface_runtime`, imported at `_toolchain/interpret.py:417` and `:434`. `replay.py:22` defines another `RUNTIME`, the text `'replay'`, so one name stands for two unrelated things.
- `src/generative_driver/client_interface.py:16`: `device_errors` is `device_client.descriptor_errors` under a second name. `help(client_interface.device_errors)` shows the function as `descriptor_errors`, a name the interface does not offer.
- `src/generative_driver/configurator.py:188`: the form of `evaluation_token_sha256` is checked only for a run on a supplied device (line 1521). A run without one keeps any value given under that key in its stored request, unchecked.
- `src/generative_driver/configurator.py:1824`: the service sends `release` to a supplied device whenever the run's worker ends, also when the run only stops and can still be resumed. `docs/client-interface.md:58` says so, and a client must expect `release` before the run is over.
- `src/generative_driver/configurator.py:3051`: the refusal of a `condition_id` that a call may not carry says "sampled-sensor", the name of a device family the tool no longer knows. A worker that meets it cannot tell what the word means.
- `src/generative_driver/daemon.py:64`: the service writes a log line for every refused request. A `status` asked by a `request_id` that started no run is refused with `Unknown request_id` (`configurator.py:1235`), as `docs/client-interface.md:117` documents, so a client that polls this way adds one line to `daemon.log` per poll.
- `src/generative_driver/dashboard.py:15`: the dashboard imports `equivalence_label` from `configurator`, which only passes the name on from `verdict_labels` (`configurator.py:27`) and never calls it. The import could name `verdict_labels` directly.
- `src/generative_driver/integrity.py:30`: the hash of a directory lists its files in the order of `sorted(path.rglob('*'))`, and `pathlib` sorts Windows paths with letter case folded. The same files can hash differently on Windows and on macOS, for example a folder that holds `NOTICE.md` and `case.json`, so a replay candidate whose hash was recorded on one system would be refused on the other (`replay.py:109`). Shown with `PurePosixPath` and `PureWindowsPath`, not run on Windows; `client.py:171` sorts the same way.
- `src/generative_driver/mcp.py:14`: the description of `driver_doctor` says "optional analysis and emulator tools". `doctor` reports `java` and `podman` and no emulator (`setup.py:374`).
- `src/generative_driver/mcp.py:79`: the approval for a run on a supplied device is the value `emulator`, also in `cli.py:52` (`--approve-emulator-tools`), `configurator.py:100`, `docs/setup.md:52` and `docs/client-interface.md:27`. The tool itself knows no emulator, so the name says less than "supplied device"; a new name would change the client interface.
- `src/generative_driver/replay.py:86`: seven lines of this file are over the 120 columns `STANDARDS.md` allows (86, 93, 104, 155, 168, 189 and 231), as are 26 lines of `supplied/stages.py` and `tests/test_client_interface.py:181`. In all, 981 lines in 61 Python files under `src/` and `tests/` are over, most of them in `tests/test_configurator.py` (377) and `configurator.py` (208).
- `src/generative_driver/scripted_worker.py:57`: `_sha256` imports `digest` inside the function. `digest` comes from the tool's own `integrity` module now, so nothing calls for an import at use.
- `src/generative_driver/supplied/_files.py:1`: the file holds two things, the finder of an artifact in a handoff and the writer of a stage's JSON files. `STANDARDS.md` asks for one responsibility per file; both helpers are small and private.
- `src/generative_driver/supplied/capabilities.py:1`: the module has a one-line doc only, because a probe worker gets the file as its rules file (`supplied/__init__.py:7`). `STANDARDS.md` asks every module doc to say why the module exists and names no exception.
- `src/generative_driver/supplied/stages.py:17`: the texts a worker gets on a supplied device call it "the provided emulator" and "the emulated device" (also lines 21, 179 and 333, `supplied/ground.py:69`, `supplied/evaluate.py:15` and `supplied/candidate_context.py:103`). The tool's term is "supplied device", and a client may supply a device that is no emulator.
- `src/generative_driver/supplied/stages.py:584`: `package-events.jsonl` is opened to append with no encoding, where the journal at line 595 gives `utf-8`. The lines are ASCII JSON today, but `docs/client-interface.md:162` names this file for clients to read.
- `STANDARDS.md:26`: the text says the serial test run takes about 13 minutes. The Run's last measurements were about 90 seconds for the test command and 224 seconds for one serial run of all tests, after the benchmark's tests had left. Not verified: no test was run for this check.
- `tests/`: about 85 tests of the tool's own behaviour were kept with the benchmark's tests, by the owner's decision of 2026-11-18, and left this repository with them in commit `23028c6`. The tool may have lost coverage. Not verified: which behaviours now have no test was not checked.
- `tests/test_checkout.py:11`: the skip reason says "checkout contract". `STANDARDS.md` says to write "interface", not "contract".
- `tests/test_client_calls.py:250`: this wait ends when the run's `status` leaves `queued` and `running`, without also waiting for `stopping` to be false; so do `tests/test_configurator.py:3827` and `:3852`, `tests/test_dashboard.py:244` and `tests/test_supplied_runs.py:926`. A test of the removed benchmark failed once on Windows because the worker was still stopping after such a wait. Not verified: whether the code after each of these waits needs the worker to have stopped.
- `tests/test_client_surface.py:261`: the test patches the private `Controller._release`, as `tests/test_service_log.py:268` does, and `tests/test_supplied_runs.py:1034` patches `Controller._generated_reuse`. `STANDARDS.md` asks tests to go through public interfaces, and a change of these names breaks the tests.
- `tests/test_device_sessions.py:24`: on Windows this module printed three `WinError 10054` tracebacks in every hosted run while it passed. `.scratch/test-noise/issues/01-quiet-test-noise.md` describes the same noise. Not verified: no Windows run was looked at for this check.
- `tests/test_distribution.py:3`: `Path` is imported and not used.
- `tests/test_service_repair.py:55`: the `finally` block uses `run`, which is assigned inside the `try` at line 27. If `start` raises, the test fails with a `NameError` that hides the first error.
- `tests/test_service_smoke.py:397`: the Ctrl-C test sends the interrupt a fixed 2 seconds after the probe folder appears (line 405) and then waits 120 seconds (line 407). It times out when the test process itself ignores the interrupt, as a process does that a non-interactive shell started with `&`. It also timed out once under load; that case is not verified.
- `tests/test_supplied_stage_files.py:67`: `if __name__ == '__main__'` stands in the middle of the file, before the last two test classes. Run as a script, the file skips the tests defined after it.
- `tests/test_tool_process.py:136`: the helper `benchmark_run` and the test at line 728 still call a run on a supplied device "a benchmark run". The same word is in test names at `tests/test_emitted_package_calls.py:46`, `tests/test_contract_authoring.py:129` and `tests/test_owner_generated_integration.py:128` and `:140`, though the tool knows no benchmark.
- `tests/test_tool_process.py:671`: the test of an `emit_check` that was stopped failed once during the Run with `KeyError: 'rejected'` and passed in every other run. It depends on timing and can fail the test command. Not verified: it was not run for this check.
- `uv.lock:172`: `cryptography` is still locked, as a dependency of `mcp` through `pyjwt[crypto]`. The tool itself no longer requires it, so nothing is wrong unless the lock was expected to drop it.
