# Driver contract format 1

`interface-package/2` freezes three checked views: authoritative `driver/contract.json` (`driver-contract/1`), authoritative `driver/protocol.json` (`driver-protocol/1`) and their executable projection `driver/model.json`. `mcp-tools.json` (`driver-mcp/1`, renderer version `2`) is deterministically rendered from the contract. The manifest inventories and pins each file. Altering the contract without updating/validating its projection and catalog fails package checks.

The contract has exactly `schema`, `device`, `identity`, `operations`, `provenance`. The protocol has exactly `schema`, `runtime_schema`, `channel`, `operations`. Both operation inventories must match. Existing model-version rules govern device, identity, provenance, operation names, channel, steps, decoders and execution bounds.

Each public operation has `effect` (`read`, `write`, `actuate`), nonempty bounded `description`, `uncertainties`, `parameters`, `outputs`, and optional `preconditions`. Every parameter/output definition has `schema`, `description`, `unit` (string or explicit `null`) and `uncertainties`. Protocol operations have only `steps` and `outputs`; they cannot redeclare effects, parameter definitions or units. Output decoder names must match public output names.

Descriptions have at most 8,192 characters. `uncertainties` contains at most 64 records, each with nonempty `code`, readable `message` and `evidence_refs` (at most 128 nonempty strings, each at most 2,048 characters). Warnings stay attached to their operation/parameter/output scope and are rendered into MCP descriptions and execution results.

Public value schemas require `type`: `integer`, `number`, `string`, `boolean` or `null`. Supported constraints are nonempty `enum`; finite ordered `minimum`/`maximum` on numbers; bounded `minLength`/`maxLength` on strings; and `contentEncoding: "hex"` with explicit even character bounds for byte arguments. Unsupported fields, schema types, references and capabilities fail acceptance. The protocol's runtime schema may further restrict parameter encodings. Numeric wire bounds do not establish physical operating limits.

Compilation rejects categorically impossible output/decoder type pairings; runtime checks enforce actual decoded values and bounds. A public operation's conservative aggregate output/evidence budget is 2 MiB, including guard observations and rejection details, leaving room in managed IPC/MCP envelopes. Oversized expansion is refused before transport opening. That refusal references the contract if the caveat list itself must be omitted.

Preconditions are a list of at most 16 equality rules, implicitly combined with AND. Each has unique `id`, readable `description`, `observation` (`operation`, constant `parameters`, `output`), `operator: "eq"` and `expected`. The observation must name an unguarded read operation and declared output. Conditions cannot perform preparation or invoke another guarded operation. The runtime obtains fresh observations under the requested operation's managed lease. False and unavailable observations have separate result codes.

`driver-result/1` retains `operation`, `ok`, `outputs`, `units`, `warnings`, structured `error` on failure, observations, transaction/transcript evidence, contract/model pins and `requested_command_dispatched`. Managed use adds `session_id`, `request_id`, `dispatch_id`, `evidence_id`. A false condition retains its ID, rule, expected/observed values. Failed operations have empty public outputs rather than fabricated success fields; invalid decoded values are recorded separately. Application tools use the same envelope and add constituent `calls`.

Historical `interface-package/1` remains checked under its original rules. Importing a historical executable model into format 2 adds explicit unknown-meaning caveats; it invents no operation or parameter semantics. See the installed project's extension guide for managed session and application authoring commands.

Renderer version 2 adds common `_request_id` invocation context. It is required for write/actuate tools and optional for reads, bounded to 1–128 characters, removed before driver dispatch and echoed in results. Public parameters cannot use this reserved name. One caller-chosen ID and argument set denotes one managed invocation; a repeat returns its durable result. Applications derive stable child IDs from the parent ID and call order. This context never changes bindings, effect grants or preconditions.
