# Open notes from the kit-fixes Run

Status: needs-triage

Findings noticed during the kit-fixes Run and left unfixed. Each was checked against the tree on 2026-11-19. The Run's records are in Git history at commit `7b53448`, under `docs/features/kit-fixes/`.

- `docs/codex.md:8`: the guide tells the user to run `codex --version`, though another program of that name may come first on `PATH`. The guide warns of this; `doctor` itself never runs a `codex` it finds on `PATH`.
- `plugins/generative-driver/.codex-plugin/plugin.json:3`: the checked-in plugin keeps version `0.1.0`, and its `.mcp.json` passes no plugin build to the server. `doctor` reports `unchecked` for a server started from it and cannot say whether that plugin is stale.
- `src/generative_driver/_toolchain/acquire.py:284`: `acquire_datasheet` writes each page file, and `index.json` at line 287, through `open(...)` without closing it; line 785 has the same form. Tests show a `ResourceWarning`, and on Windows the files can stay locked until garbage collection.
- `src/generative_driver/_toolchain/emit.py:342`: a register package passes only if its Python equals the templates of the installed tool. A register package made by an earlier version is refused after any upgrade that changes a template.
- `src/generative_driver/_toolchain/interpret.py:171`: sizes and waits that a worker chooses have no upper limit: `random_files` here and at line 247, `n` at `_toolchain/probe.py:63`, `seeds` at `_toolchain/emit.py:370` and `:438`, and `delay_ms` at `resources/tools/model_exec.py:79`. In a generic run only the 570 seconds of one tool call bound the work.
- `src/generative_driver/_windows_worker.py:56`: the Windows launch wrapper reports only the message of a launch that failed. The service's log gets no traceback for it.
- `src/generative_driver/agents.py:272`: a run's `runtime_version` is read from `config.get('version')`, and so is `agent.version` at `configurator.py:1296`. `configure` never writes that key, so both are null unless a client puts `version` into `executor_config`, and no run records its runtime's version.
- `src/generative_driver/agents.py:327`: a line a worker writes to standard error is saved but not passed on as an event. `status.worker` shows no sign of life for a worker that writes only there.
- `src/generative_driver/cli.py:66`: `setup` prints a raw traceback when the output folder holds something it did not generate (`ValueError`). A one-line message would tell the user what to do.
- `src/generative_driver/client.py:287`: on macOS the service socket is `<temporary directory>/gd-<20 hex>/owner.sock`. With a temporary directory longer than about 68 bytes the path is too long for a Unix socket, and the service cannot start.
- `src/generative_driver/client.py:288`: each home leaves an empty `gd-<identity>` folder in the system temporary directory. The service removes only the socket (`daemon.py:127`), so every smoke leaves one folder behind.
- `src/generative_driver/client.py:368`: `call(..., autostart=False)` answers `{'ok': False, 'reason': ...}` with no `error` when the service is not reachable, so a caller can tell it from a refusal only by its text. `docs/client-interface.md:5` lists three replies without `error` and not this one.
- `src/generative_driver/configurator.py:1418`: when `resume` finds an integrity fault on a cancelled run, it calls `_state(run_id, 'blocked', ...)`, which changes nothing while the run's `cancelled` flag is set (line 1212). The run stays `cancelled` and no event records the fault.
- `src/generative_driver/configurator.py:1460`: `_configured_executors` raises on a `config.json` that is not valid JSON or not an object. A `start` is then refused with the bare `JSONDecodeError` or `AttributeError` text, which does not name the file, where `doctor` gives a reason.
- `src/generative_driver/configurator.py:2141`: the service prepares an interpret stage by calling `interpret_run` inline, with no deadline, and `supplied/stages.py:344` does the same. Worker tool calls and the service's checks run in a child process with a limit; a preparation that hangs holds its run.
- `src/generative_driver/configurator.py:2142`: every interpret stage makes a `gd-candidate-*` workspace in the system temporary directory, as `supplied/stages.py:346` does, and every interpret task a `gd-task-*` one (`interpret_tasks.py:399`). Nothing in the tool removes them, so they pile up with each run and each smoke.
- `src/generative_driver/configurator.py:2931`: each of the service's own checks gets a fresh 570 seconds (line 2940). A model whose conversion module loops costs up to 570 seconds at interpret and again at each later stage that validates it, until the run's budget ends.
- `src/generative_driver/configurator.py:3068`: 208 lines of this file are longer than the 120 columns `STANDARDS.md` allows; this one is the longest, at 204. `mcp.py:74` and `:82` and `tests/test_cli.py:86`, `:90`, `:96` and `:292` are over too.
- `src/generative_driver/daemon.py:67`: a reply that cannot be written as JSON, such as a result that holds NaN, raises `ValueError`, which the `except (OSError,EOFError)` at line 68 does not catch. The request thread ends without a reply, and the client reports a lost reply.
- `src/generative_driver/device_access.py:271`: the child of a managed device session runs with `-I -S -B`, and `-S` leaves out site-packages, which `emit_test_live` keeps (`_toolchain/interface.py:589`). A session over a serial, USB or FTDI binding would therefore fail for a missing optional dependency even with the hardware extra installed. Read from the code, not run.
- `src/generative_driver/resources/toolchain/tools.json:1182`: the `emit_check` text says archived runtimes "remain verifiable without executing their code", and the `emit_test_live` text at line 1243 says a package runs "through its own command line". The tool now runs its installed runtime over a copy of the package's data (`_toolchain/interface.py:380`), so workers read a description of earlier behaviour.
- `src/generative_driver/resources/tools/model_exec.py:56`: the path of a model's conversion module is `conversion.module` joined to the model's folder, unchecked; the same join is at `_toolchain/interpret.py:228` and `_toolchain/emit.py:264` and `:332`. A model can name a file outside its folder, and the tool loads and runs it.
- `src/generative_driver/setup.py:42`: `configure` reads `config.json` without an encoding and raises `JSONDecodeError` when it is not valid JSON. `doctor` names such a file, but the user must fix or remove it by hand before `configure` works.
- `src/generative_driver/setup.py:51`: `configure` writes `config.json` through a temporary file and `os.replace`, and `_record` at line 201 does the same for `setup.json`. The two could share one helper.
- `src/generative_driver/setup.py:232`: the result keys `build`, `replaced` and `replaced_build` are in double quotes, where `STANDARDS.md` asks for single quotes. They follow the older lines around them.
- `src/generative_driver/setup.py:389`: `doctor` takes `core.platform` from `platform.platform()`, which on macOS runs `uname -p` and `file -b` from `PATH`. So `doctor` runs two programs the operator did not configure, and the value can change with `PATH`.
- `src/generative_driver/tool_process.py:105`: the service looks whether a tool call's limit has passed only every 0.05 seconds, so a tool that ends just after its limit and before the next look still returns its result. Starting the child cost about 0.05 to 0.3 seconds when the Run measured it; not verified, since nothing was measured for this check.
- `tests/test_cli.py:51`: ten child launches of `python -m generative_driver` get the inherited environment (lines 51, 87, 90, 107, 121, 152, 167, 204, 219 and 228). `STANDARDS.md` asks for the environment of `tests/package_env.py`, so that a child cannot run another checkout's code.
- `tests/test_service_lifecycle.py:318`: this test covers a shutdown during a tool call that runs in a child process. Not verified: no test seems to cover a shutdown while a call runs inline, as the calls of a run on a supplied device and of a device session do; test names and uses of `shutdown` were searched, not every test body.
- `tests/test_service_log.py:286`: tests call private parts of the service: `_release` here, `_device_call` at line 302, `_event` at 322 and `device_recovery.reconcile` at 335. Tests also write run rows straight into the home's database (`tests/test_service_log.py:220` and `:246`, `tests/test_run_status.py:144`, `tests/test_tool_process.py:149` and `:173`), so a change of those names or of the table breaks them.
